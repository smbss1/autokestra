# v0.1 Release Gate

This is the minimum set of checks to run before tagging v0.1.

## Local

From the repo root:

- `bun run lint`
- `bun run test`

## Optional: build artifacts

- `bun run build`

### CLI standalone executable

- `cd packages/cli`
- `bun run build:exe`

This produces `packages/cli/dist/autokestra` (OS/arch-specific).

## Runtime budget

CI runs `bun run test` on `ubuntu-latest`. Keep new integration-style tests lightweight:
- prefer in-process `createApp().fetch(...)` over binding network ports
- prefer temp SQLite files over external services
- avoid Docker in CI unless explicitly gated/optional

## Plugin execution model guardrail

Before release, verify plugin runtime still executes plugins out-of-process via `bun run index.ts` and does not switch to in-process execution.

For `core/bash.exec`, verify shell commands/scripts are executed through the same child-process plugin boundary and that non-zero exit codes fail tasks deterministically.

## Plugin registry gate (v0.2 track)

Before shipping plugin registry capabilities, verify:

- Reproducible install: installing the same `namespace/name@version` resolves to immutable artifact + identical checksum.
- Checksum enforcement: install fails deterministically on digest mismatch for official, GitHub, and direct URL flows.
- Rollback behavior: removing active version auto-activates previous version by default; `--no-rollback` disables this behavior.
- Retention policy: install state keeps at least 2 versions per plugin (active + previous).
